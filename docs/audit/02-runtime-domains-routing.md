## Environment separation and secrets
- **Production worker (`worker/wrangler.toml`)**: Uses `GOOGLE_SCOPES`, `GOOGLE_REDIRECT_URI`, `DEFAULT_USER_KEY`, `MAILCHANNELS_DOMAIN`, `MAIL_FROM`, `MIRA_TASKS_DB_ID`, `MIRA_ROOT_PAGE_ID`, `OPENAI_CHAT_MODEL`, and `DASHBOARD_URL` (`worker/wrangler.toml:9-24`). `ASSISTANT_KV` namespace ID `f941315e760f46a494dd17e1f9d967e2` stores tokens. Cron `*/10 * * * *` fires reminder processing, and observability logs are enabled (`worker/wrangler.toml:25-33`).
- **Development worker (`wrangler.personal-assistant-dev..toml`)**: Mirrors production variables but reuses the same KV names and cron; useful for local `wrangler dev` runs (`wrangler.personal-assistant-dev..toml:1-30`).
- **CI secrets**: `.github/workflows/deploy-mira.yml` uses `${{ secrets.CF_API_TOKEN }}`/`${{ secrets.CF_ACCOUNT_ID }}` while `deploy-site.yml` and `deploy-worker.yml` rely on `${{ secrets.CLOUDFLARE_API_TOKEN }}`/`${{ secrets.CLOUDFLARE_ACCOUNT_ID }}` (see each workflow for the exact names). Ensure both sets of secrets resolve to the same Cloudflare account so deployments succeed.

## Verification actions for unknowns
- **DNS / Pages mappings**: Use the Cloudflare dashboard (Workers > `Routes`, Pages > `Custom domains`) to confirm where `elyra-core.app`, `app.elyra-core.app`, and `mira-assistant.elyra-core.app` are pointed. If the dashboard is unavailable, run `curl -I https://<domain>` and inspect the `server` header to infer the provider.
- **App hosting**: The repo does not include a workflow for `fish-delish-site`; confirm whether `app.elyra-core.app` is built via a separate pipeline (e.g., `npm run build` then copy to another host) outside this repo. Document the owning build job once identified.
- **Pitchdeck domain**: Check Cloudflare DNS for `pitchdeck.elyra-core.app` or run `nslookup`/`dig` to see whether it resolves to Cloudflare Pages or Workers. If it does, add the pairing to this table.
