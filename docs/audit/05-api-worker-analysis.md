# API / Worker Analysis

## Overview
The Cloudflare Worker entry point is `worker/src/index.ts`, compiled via `worker/package.json` and deployed with `wrangler` (`worker/wrangler.toml`). It exposes REST endpoints for Merlin (`/assistant/*`), email intelligence (`/assistant/email/*`), calendar operations, Drive/Slides/Knowledge access, memo/testing helpers, and Google OAuth flows. A scheduled cron (`*/10 * * * *`, `worker/wrangler.toml:25-27`) runs `processCalendarReminders` so reminders can be surfaced via `/assistant/calendar/reminders`.

## Auth & token storage
- `loadGoogleTokens`/`saveGoogleTokens` wrap `ASSISTANT_KV` with the key prefix `google_tokens:${userKey}` (`worker/src/index.ts:10-33`).
- `refreshGoogleAccessTokenIfNeeded` enforces `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, uses the stored refresh token, and rewrites the KV entry on success (`worker/src/index.ts:22-80`).
- User scoping: `resolveCalendarContext`/`resolveDriveContext`/`resolveSlidesContext` call `extractContextValue` so `userKey`, `workspaceId`, and `locationId` can come from query/body/header, and fallback to `env.DEFAULT_USER_KEY` (`worker/src/index.ts:717-739`).
- OAuth fallback: `handleGoogleAuth`/`handleGoogleCallback` (`worker/src/index.ts:2006-2052`) leverage `GOOGLE_SCOPES`, `GOOGLE_REDIRECT_URI`, and `DEFAULT_USER_KEY` (set in `worker/wrangler.toml:9-18`). After each callback the tokens are stored in KV for reuse.

## CORS and context
- CORS only allows `https://app.elyra-core.app`, `https://pitchdeck.elyra-core.app`, and `https://personal-assistant.fish-delish.workers.dev` (`worker/src/index.ts:667-693`). The helper `allowCorsResponse` attaches the guard and sets `Access-Control-Allow-Credentials`, matching the SPA’s `fetch(..., { credentials: "include" })` in `mira-app/js/merlin-client.js`.

## Additional mechanics
- **KV prefixes**: `slides:`, `slides:index:`, `knowledge:`, `google_tokens:`, `reminder:` (as seen in `listSlideDecks`, `listKnowledgeItems`, `processCalendarReminders`).
- **Scheduled reminders**: `processCalendarReminders` (lines 2540-2630) fetches upcoming events and writes reminder payloads to `env.REMINDER_SENT` KV, limited by `REMINDER_LOOKAHEAD_MINUTES`. The scheduled handler `scheduled` simply calls this helper (`worker/src/index.ts:3150-3185`).
- **Error handling**: Most endpoints wrap external API calls (`fetch`) in try/catch, log via `console.error`, and return `buildJsonResponse` with `ok: false` and `detail`. When OpenAI fails, the worker falls back to heuristics (`buildFallback*` functions near lines 880-1200). 
- **Observability**: `worker/wrangler.toml:28-33` enables invocation logs (`head_sampling_rate = 1`, `persist = true`).

## Missing pieces / risks
- No HTTP 401 is currently emitted, so `mira-app/js/mira.js`'s `auth:required` event never fires—this makes the worker incorrectly allow unauthenticated API calls. Adding a gate (see Auth doc) is urgent in production.
- Domain routing (`api.elyra-core.app`) is defined outside the repo; verify the route in the Cloudflare dashboard to ensure workers are bound to the public API host.
