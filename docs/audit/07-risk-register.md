# Risk Register

## Technical Risks
1. **Unauthenticated access to `app.elyra-core.app` and API** — `worker/src/index.ts` never returns `401`, so `mira-app/js/merlin-client.js` never fires `auth:required` despite relying on access tokens, and `fish-delish-site/index.html` exposes the workspace link to anyone. Impact: public access to calendar/email data. Mitigation: implement the auth gate described in `03-auth-login-flow.md` so `/assistant/*` endpoints reject missing sessions and the marketing CTA cannot reach the app without a valid cookie.
2. **Worker deployment lacks dependency installation** — `.github/workflows/deploy-worker.yml` runs `wrangler deploy` without `npm ci` inside `worker/`, so the `tsc` build and TypeScript dependencies (`worker/package.json`) are missing. Impact: deploys fail in clean environments. Mitigation: insert `npm ci && npm run build` before `wrangler deploy` (see `worker/package-lock.json`) and cache `~/.npm` if needed.
3. **Page deployment duplication and missing workspace deployment** — Two nearly identical workflows (`deploy-mira.yml`/`deploy-site.yml`) target the same `mira-assistant` Pages project, yet there is no workflow for `fish-delish-site`. Impact: confusion, redundant builds, and no automation for the workspace app. Mitigation: consolidate Pages workflows and add a new workflow that builds/deploys `fish-delish-site` (e.g., via Cloudflare Pages or another host).
4. **External-service failure cascade** — Many endpoints call Google APIs, OpenAI, and Notion (see `worker/src/index.ts:3700-4200`). Missing API keys cause 500 errors that bubble up to the UI. Impact: workspace features fail silently. Mitigation: add retries with exponential backoff, fallbacks (already in place for emails), and monitor failures through Cloudflare logs (`wrangler.toml` observability block). Ensure secrets (`OPENAI_API_KEY`, `GOOGLE_CLIENT_ID/SECRET`, `NOTION_TOKEN`) are rotated regularly.

## Product Risks
1. **App accessible without login** — Without an auth gate the workspace behaves as an open demo rather than a workspace, undermining the marketing promise that clicking “Login” unlocks a private dashboard (`fish-delish-site/index.html:20-30`). Mitigation: enforce the login flow (Option A) so only authenticated visitors reach the workspace and document the login state transitions for the demo script.
2. **Feature expectation mismatch** — The UI shows panels for Calendar, Mail, Slides, Knowledge, Tasks, but most endpoints return stubbed data (e.g., `buildDashboardSummary` returns static stats, the Planner view is a placeholder). Impact: investors/users expect live data but currently see canned content. Mitigation: clearly document which panels are live vs stubbed (in demo script/backlog) and prioritize the integrations in the backlog (see `08-backlog-epics-stories.md`).

## Legal / DSGVO Risks
1. **Persistent storage of emails/calendar items** — The worker stores Gmail tokens, parsed emails, slides, and reminders in Cloudflare KV (`ASSISTANT_KV`). Without consent tracking or deletion workflows, this could violate data-retention requirements. Mitigation: add a DSGVO compliance epic (see `08-backlog-epics-stories.md`) that introduces consent capture, delete-on-demand, and audit logs for stored KV keys (document the keys `google_tokens:`, `knowledge:`, `slides:`, `reminder:` so operators can purge them).
2. **Email intelligence uses OpenAI and Notion** — Summaries/drafts/risks are sent to third-party APIs, raising data transfer concerns. Mitigation: Flag this in the backlog (DSGVO epic) so the legal team can review OpenAI/Notion data handling, provide a data-processing agreement, and optionally pseudonymize sensitive fields before sending.
